# 伊莫 · 虹天气捕捉净成本计算器

比较谜立方、超级立方、究极立方，**触发一次虹天气即完成**的期望净金币花费。支持15类目标权重或单一基础概率、两种权重口径、正背面比例、等级差、两种捕获加成口径、普通与虹能+50%滋养的独立次数，以及基础汇报金币加成。每条主要公式附变量、单位和数据来源。

在线使用：<https://uiharuayako.github.io/yimo-kira-cost/>

## 本地运行

需要 Node.js 22.12 或以上版本。

```sh
npm ci
npm test
npm run build
npm run dev
```

打开 `http://127.0.0.1:4173/`。公式与字体从本站加载；不依赖外部CDN，配置只保存在浏览器本机。

## 默认设置与来源

- 默认15类配比：后期区域·成熟期权重1，其余14类为0。也可切换单一目标，直接输入基础捕获率，默认16%，此时完全忽略15项权重。
- 正面70%、背面30%，可互补编辑；背袭倍率1.5。
- 等级差是伊莫等级减联结者等级；默认10代表≤10无惩罚档，允许负整数。
- 全部战斗外捕捉普通、非头目伊莫，状态系数1；满血的战斗内0.8不参与。
- 捕获加成数值默认1%，可编辑。默认最终加算口径，1%指加1个百分点；可切换官网乘算口径，1%指基础概率先乘1.01。各正背分支分别封顶100%。
- 三种立方单价3500/7000/10500金币由用户提供；倍率1/1.5/2来自官网。
- 普通滋养与虹能+50%滋养各自输入次数，默认都为0，可只用其中一种或同时使用。每次未直出分别增加480与720虹能，直接天气概率都为3%；不设置先后顺序，精华自身成本不计。
- 用户确认基础汇报1200金币，加成30%时实收1560。加成默认30%，可编辑；只扣基础返还，不含资质、幽黯等额外奖励。

概率、等级系数、幸运档位、保底、480虹能和直接天气概率来自[官网概率公示](https://www.yimo.com/formula-multipliers)，核对日期2026-10-30。虹能+50%及直出概率不变是用户提供的规则，由此计算720=480×1.5；基础汇报1200也是用户确认值，两者不应标为官网已公示。

## 捕获概率

设基础率b、立方倍率m、背面占比β、等级差Δ、等级倍率L、捕获加成率η（1%写作0.01）：

| 等级差Δ | L |
| --- | ---: |
| ≤10 | 1 |
| 11 | 0.8 |
| 12 | 0.6 |
| 13 | 0.4 |
| 14 | 0.2 |
| ≥15 | 0.1 |

```text
最终加算：
p_front = min(b × m × L + η, 1)
p_back = min(b × m × L × 1.5 + η, 1)
官网乘算：
p_front = min(b × (1 + η) × m × L, 1)
p_back = min(b × (1 + η) × m × L × 1.5, 1)
p = (1 − β) × p_front + β × p_back
α_i = w_i / Σw_j
投掷目标占比：P = Σ α_i p_i
成功捕获占比：P = 1 / Σ(α_i / p_i)
```

前一种每次投掷选择类型；后一种选择目标后持续投掷直到成功再换下一只。逐类、逐分支封顶后才能加权，不能先平均基础率。

单一目标模式直接取P=p，不进行权重归一化或调和平均。输入的是基础概率，不是最终捕获率；仍应用立方、等级、正背和所选加成口径。输入0基础率时，最终加算1%仍有1%捕获率；官网乘算下始终为0，若仍需捕获则没有有限的完成成本，页面会给出无法捕获提示。切回配比模式不会被隐藏的单一概率输入阻塞，反之亦然。

## 天气停止时间

精华每次3%直接天气、每次普通/超级幸运事件0.6%直接天气、虹能累计10500保底，**任一个完成就停止**。

普通计划次数为u，加成计划次数为v，均为非负安全整数。两项独立合并，不设使用顺序：

```text
计划次数 a = u + v
计划虹能 E = 480u + 720v
剩余保底 r = max(10500 − E, 0)
若 r > 0：
  全部计划精华未直出概率 s = 0.97^a
  精华阶段直出概率 = 1 − s
  E[N] = s × K_weather(r)
若 r = 0：
  P(N=0)=1，E[N]=0
```

K_weather(r)是所有计划精华均未直出的条件下，捕获到幸运直接天气或虹能达到r所需的成功捕获次数期望。精华阶段已成功的路径不产生后续捕获支出或返还。仅普通滋养22次、仅加成滋养15次，或其他总计划虹能达到10500的混合，都无需捕获。

计划总能量达到保底时，实际会在精华直出或保底时提前结束；两个总次数不足以唯一确定两类实际消耗或“直出/保底”各自占比，因此页面不再拆分这些概率，也不假设顺序。这个差别不影响成功捕获分布和立方花费：它们都为0。计划虹能不代表所有计划精华实际都会消耗。

当前结果来自500万条共享事件跳跃路径，种子2026103041，各门槛记录首次过线或首次天气的停止次数。因为480和720的最大公约数是240，统一数据覆盖10500、10260、…、180这44档门槛。没有按剩余能量线性缩放；共享路径的各门槛估计相互相关。原普通滋养的22档均值和完整整数频次与旧数据逐项完全一致。

默认0次精华E[N]=2576.3470804，标准误约0.3885732，均值95%蒙特卡洛区间约[2575.5854909,2577.1086699]。区间是模拟均值的估计误差，不是单个玩家的95%预算范围，不包含规则假设误差。

## 完成次数分布与幸运档位

分布统计的是**触发天气前的成功捕获只数N**，包含触发天气的最后一只，不含失败投掷。三种立方共用这一分布；捕获概率影响投掷费用，不改变成功捕获之后的幸运机制。不能直接把次数分位数除以捕获率当作用球数分位数。

`data/weather-thresholds.json`记录500万条共享路径、44个剩余虹能门槛在每个整数次数上的完整频次、条件均值及其估计误差。浏览器用`src/distribution.js`合并两类精华的零捕获分支；图表分箱只用于展示，区间和分位数从原始整数PMF/CDF计算。`data/weather-distribution.json`保留为普通滋养的22档参考。

设h_r(t)为剩余门槛r、精华均未直出的条件捕获分布，s=0.97^(u+v)，则：

```text
r > 0: P(N=0)=1-s，P(N=t)=s×h_r(t)，t≥1
r = 0: P(N=0)=1
F(k)=P(N≤k)
P(a≤N≤b)=F(b)-F(a-1)    （整数闭区间）
幸运pL = Q(1-L/100)，L为95、80、50、30、10
Q(τ)=满足F(k)≥τ的最小整数k
p100 = 理论最小可完成次数
```

按用户指定的幸运方向，p95对应完成次数下尾5%的分位门槛；这些是分位次数，不是分组期望。离散分布允许多个幸运档位相同，不插值成小数；有并列时不表示严格超越相同比例的玩家。默认不使用精华时p100=1；使用精华后可能直接出天气，p100=0。p100表示最幸运可行结果，不表示100%的玩家都能在一次内完成。

| 默认幸运档位 | p100 | p95 | p80 | p50 | p30 | p10 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 成功捕获只数 | 1 | 651 | 1996 | 2674 | 3068 | 3576 |

默认分布标准差约868.876，偏度约−0.775；提前天气形成左尾、保底可形成离散突峰，因此不按正态分布拟合。标准差描述玩家间波动，与均值的蒙特卡洛标准误不同。先前引用的95%均值区间不能当作玩家次数分布区间。

默认0次精华时，首抓直接天气的解析概率为(0.002+0.998×0.01)×0.006=0.007188%；它是理论最小次数存在的依据。直方图的首抓频率来自有限模拟，可能与解析概率有差异。精华较多时首抓还可能通过剩余虹能保底完成，因此“首抓直接天气概率”不总等于“首抓完成概率”。图表最大次数为样本最大值，不是理论最坏保底。

## 立方支出、基础汇报返还、净费

设立方单价c、汇报加成γ（30%用0.30表示）：

```text
每只基础汇报实收 = 1200 × (1 + γ)
期望用球数 = E[N] / P
期望立方支出 = c × E[N] / P
期望基础汇报返还 = E[N] × 1200 × (1 + γ)
期望净花费 = 期望立方支出 − 期望基础汇报返还
```

包含触发天气的最后一只，每次成功捕获均提交汇报。净费允许负值，表示模型范围内预计净收益；未计精华自身成本、资质额外奖或其他资源机会成本。金额单位金币，页面用万金币。

| 默认立方 | 捕获率 | 期望立方支出 | 基础汇报返还 | 期望净费 |
| --- | ---: | ---: | ---: | ---: |
| 谜立方 | 19.4% | 4648.0万 | 401.9万 | 4246.1万 |
| 超级立方 | 28.6% | 6305.7万 | 401.9万 | 5903.8万 |

## 必要假设与复算

- 初始虹能、本周普通/超级次数、两类保底计数均0；不跨周。
- 所有成功捕获均符合幸运判定，失败不推进幸运计数。
- 先判超级，未触发才判普通。各类保底仅触发本类时重置；超级当次暂停普通保底累计，后一点是官网未完全说明的实现细节。
- 普通和超级事件各按0.6%直接天气，未直出增加虹能；两类精华都按独立3%直出，未直出分别增加480/720。
- 正背、等级、立方与汇报加成不改变成功捕获之后的幸运机制。

当前44档元数据与整数频次在 `data/weather-thresholds.json`，浏览器查表在 `src/weather-threshold-data.js`。原22档普通滋养参考在 `data/weather-results.json`、`data/weather-distribution.json` 和对应模块，供回归核对。复算需要Python与NumPy：

```sh
python scripts/simulate_weather.py --samples 5000000
python scripts/simulate_weather_distribution.py --samples 5000000
python scripts/simulate_weather_thresholds.py --samples 5000000
python -m unittest discover -s tests -p 'test_*.py'
```

旧 `data/model-results.json`、`data/essence-results.json`、`src/energy-estimates.js` 及两份旧模拟脚本仅保留为严格累计虹能、不提前停止天气的历史结果，不用于当前页面。
